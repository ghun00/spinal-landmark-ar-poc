# Spinal Landmarking AR PoC — 설계 문서

작성일: 2026-11-08
상위 명세: `Spinal_Landmarking_AR_PoC_Spec.md` (v1.2). 이 문서는 명세를 대체하지 않고, 명세가 개발자에게 맡긴 결정과 구현 구조를 정함. 명세와 충돌하면 명세가 우선.

## 1. 의도

다른 연구원이 실험 준비 중 스마트폰(Galaxy S25 / Chrome) 웹주소만으로 열어, 빨간 원형 스티커 3개(C7, 좌·우 PSIS)를 인식하고 선택한 척추 레벨의 비율 기반 추정 위치를 실시간으로 보는 PoC. 완료 기준은 기능 동작이며 해부학적 정확도는 주장하지 않음.

## 5. 설정 파일

`config/ratios.json`: `{ source, sourceUrl, denominator: "C7→S2 (PSIS midpoint as 100%, PoC assumption)", version, levels: [{name, ratio}] }` 13개, 명세 §4 표 값 그대로. 웹과 Python이 같은 파일을 읽음.

`config/detection.json`: 빨강은 HSV Hue가 0과 180 양끝에 걸리므로 두 범위를 OR 결합. 초기값(개발자 결정, 실물 테스트 후 조정):
- H ∈ [0,10] ∪ [170,180], S ≥ 100, V ≥ 70 (OpenCV 8비트 HSV 기준)
- 처리 해상도: 긴 변 640px로 축소 후 검출, 중심 좌표는 원본 좌표로 환산
- 형태학적 열기·닫기 커널 3–5px
- 면적: 처리 프레임 면적의 0.005%–2%
- 원형도 4πA/P² ≥ 0.70
- 분류: C7은 두 PSIS보다 위에 있고 최소 수직 간격 ≥ 프레임 높이의 10%

## 6. 처리 흐름

검출 (Python과 JS 동일): RGBA → RGB → HSV → 두 범위 inRange → OR → 열기·닫기 → 외곽선 → 면적·원형도 필터 → 모멘트 중심.

분류:
- 후보가 정확히 3개가 아니면 **무효** (0–2개: 가림, 4개 이상: 모호).
- y 오름차순 정렬. 가장 위 1개 = C7, 아래 2개 중 화면 왼쪽 = L-PSIS, 오른쪽 = R-PSIS (명세 §6: 비반전 후방 촬영에서 화면 왼쪽 = 대상자 왼쪽).
- C7이 두 PSIS 모두보다 최소 간격 이상 위에 있지 않으면 무효.

좌표: 명세 §5 공식 그대로 `P = C + r(M − C)`, 원본 영상 좌표에서 계산.

평활화: 기본은 **없음** (개발자 결정). 무효 프레임에서는 즉시 숨김. 실기기에서 떨림이 크면 연속 유효 구간에서만 마커 중심에 약한 EMA를 넣고, 무효가 되면 즉시 초기화. 숨김 규칙은 변하지 않음.

## 7. 표시

- **단일 캔버스 렌더링**: 카메라 프레임을 캔버스에 직접 그리고, 같은 변환 행렬로 오버레이를 그림. `<video>`는 숨김. 영상과 오버레이가 구조적으로 같은 변환을 쓰므로 어긋날 수 없음.
- 맞춤 방식은 **contain**(전체 프레임 표시, 여백 허용). cover를 쓰면 검출된 마커가 화면 밖으로 잘릴 수 있어서 택하지 않음. (개발자 결정)
- devicePixelRatio를 반영해 선명하게 그림.
- 오버레이: 검출 마커 원과 `C7` / `L-PSIS` / `R-PSIS` 라벨, C7→M 기준선(옅게), 선택 레벨 점과 이름.
- 라벨 배치: 점의 오른쪽에 배치하고 y 순으로 정렬, 겹치면 아래로 밀고 밀린 경우 연결선 표시. 점은 움직이지 않음. 오른쪽 공간이 없으면 왼쪽.
- 화면 하단에 상시 문구 "비율 기반 추정 위치 · 해부학적 정확도 미검증".

### 진단 화면 (개발자 결정)

`?debug=1`이면 빨강 마스크 축소 미리보기, 후보 수, 후보별 면적·원형도, 무효 사유를 화면에 표시. 사용자가 S25에서 실패 상황을 화면 캡처로 전달하면 임계값을 조정하기 위한 것. 앱 자체의 저장 기능은 추가하지 않음. 일반 화면에는 노출하지 않음.

## 8. 화면과 상태

모바일 세로 화면 하나로 구성. UI 문구는 한국어 (개발자 결정).

상태: `idle`(안내 + 카메라 시작) → `loading-cv`(OpenCV 로딩, 실패 시 재시도) → `requesting`(권한 요청) → `live-searching` / `live-tracking` → `frozen`; 그리고 `error`(권한 거부 / 카메라 없음 / 사용 중 / HTTPS 아님 / 기타, 원인별 안내와 재시도).

- OpenCV 로딩은 페이지 진입 즉시 백그라운드로 시작. 카메라 시작 버튼은 누를 수 있되, 분석은 OpenCV 준비 후 시작.
- 레벨 선택: 13개 토글 칩 + 전체 선택 / 전체 해제. 기본 선택 T1/T7/L1/S1. 선택은 저장하지 않음 (새로고침 시 기본값).
- 정지 버튼은 `live-tracking`에서만 활성화. 정지 시 그 프레임의 캔버스 이미지와 마커 좌표를 메모리에 보관. 정지 중 레벨 선택 변경은 보관된 마커 좌표로 다시 그림.
- 재개 시 보관한 프레임과 좌표를 폐기하고 실시간 검출로 돌아감.
- 카메라 요청: `facingMode: {exact: "environment"}`, 실패하면 `"environment"`로 재시도. 해상도는 1280×720을 ideal로 요청. 좌우 반전 없음.
- 분석 루프: `requestVideoFrameCallback` 우선, 없으면 `requestAnimationFrame`. 직전 프레임 처리 중이면 건너뜀.

## 9. 검증 계획

1. **Python 기준 (pytest)**: `synth.py`가 피부톤 그라데이션 배경 + 빨간 원 3개를 기대 좌표와 함께 생성. 시나리오: 정상(크기·위치·밝기 변화), 소폭 회전, 마커 1개 가림(→ 무효), 빨간 물체 추가로 4개(→ 무효), 비원형 빨간 물체(→ 무시), C7이 위에 있지 않음(→ 무효). 검출 중심 오차 ≤ 1.5px, 분류와 유효 여부 일치.
2. **JS 순수 로직 (node --test)**: 명세 §5 예시(T7 → (100, 256.16)), 분류 규칙, contain 변환 왕복, 라벨 비겹침.
3. **Python ↔ OpenCV.js 동등성 (node --test)**: node에서 `vendor/opencv-4.13.0.js`를 로드해 fixture RGBA raw에 같은 검출을 돌리고, Python 결과와 중심 ±1px 이내·유효 판정 일치 확인.
4. **브라우저 확인**: 로컬 정적 서버 + Chrome에서 `?test=1`(개발용 이미지 입력)으로 합성 이미지 넣어 오버레이·정지·재개·레벨 선택 확인. 웹캠이 있으면 실시간 경로도 확인. `?test=1` 경로는 일반 화면에 노출되지 않음.
5. **실기기 (사용자 수행)**: README에 명세 §9 체크리스트를 S25 점검표로 제공. 개발자는 미검증 항목을 완료로 보고하지 않음.
